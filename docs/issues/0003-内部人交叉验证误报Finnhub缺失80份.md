# 0003 内部人交叉验证误报"Finnhub 缺失 80 份申报"

- 日期：2026-09-13
- 影响：每天一条 Bark 推送"内部人数据交叉验证｜Finnhub 缺失 N 份申报（已回填 0 笔）"，状态页交叉验证卡片常年标黄列出几十份申报；页面数据本身没有缺
- 状态：已修复待验证（d342dc5，2026-09-13，尚未发版）

## 现象

2026-09-13 00:47 UTC 守护进程推送：EDGAR 有 Form 4 但 Finnhub 超过 2 天仍无对应交易，共 80 份（NVDA、SMCI、CBRS、DELL……全是 09-08 申报），"已从 EDGAR 回填 0 笔到页面"。之前几天也在推，只是每天的申报集合不同所以签名变化、每天都推。

## 根因

3bb56d2（2026-09-06）之后 EDGAR 通道当天就把 Form 4 的买卖写进内部人交易表（source=edgar）。Finnhub 轮询晚一两天送到同一笔时，撞上 matchKey 唯一索引被当重复丢掉，于是库里再也不会出现 source=finnhub 的行。交叉验证 `checkInsiders` 却仍按"只看 Finnhub 来源的行"核对（`source: { $ne: 'edgar' }`），EDGAR 抢先入库的每一份自然都被判成"Finnhub 缺失"；回填逻辑发现这些申报按 accession 已有交易行，所以回填 0 笔。

证据（生产库 2026-09-13）：窗口 09-06~09-11 内 Form 4 共 98 份、含 P/S 的 80 份；这 80 份在交易表里全部有 source=edgar 的行（87 笔）；最后一条 source=finnhub 的行创建于 09-06 15:25 UTC，正是 3bb56d2 发版当天；守护进程 `[insider]` 每轮"无新增内部人交易"。

## 处理

2026-09-13：
- `checkInsiders` 改为核对"页面读的交易表有没有这份申报的买卖"，不分来源。
- 回填之后再核对一次，只有回填后仍然缺的才算 `missing`、才推送、才标黄；新增 `backfilledFilings` 字段。
- 推送标题改为"交易表缺失 N 份申报"，状态页中英文案同步改。
- 没有做的：Finnhub 内部人链路的覆盖率现在无法度量（它送到的都是重复），已接受——它只是 EDGAR 通道的兜底。

## 验证方法

发版后次日 00:4x UTC 看 `docker logs happystock-monitor-1 | grep xcheck`，应为"回填 0 份 / 0 笔，仍缺 0"，无 Bark 推送；状态页交叉验证卡片内部人栏显示"交易表无缺失"。
